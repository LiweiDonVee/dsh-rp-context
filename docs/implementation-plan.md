# Active RP Context Implementation Plan

> Use superpowers:subagent-driven-development. User approved implementation; source-reference analysis is advisory and cannot override the accepted design.

**Goal:** Independently manage reversible RP narrative history and bounded GM database/material selection before the existing writer.
**Spec:** E:/WorkSpace/repos/dsh-rp-last-step/docs/context-database-design.md.
**Architecture:** Pure context store and planner, native Session projection/owner routes, React inspector. Optional rpDatabase and rpLastStep integration via services, no hard imports across repositories.
**Tech Stack:** Node24, Node test, esbuild, React18, Vitest, pnpm11.

## Global Constraints

- History comes only from canonical accepted RP narrative source records; inactive branches, failed drafts and user proposals never become facts.
- No NPC ACL. Plain narrative notes guide GM. Human database policies are enforced by database capabilities, not prompt text.
- Raw narrative remains in DSH; representation changes do not delete it or replace the host compaction backend.
- Model calls are isolated bounded JSON workflows; no arbitrary endpoints from model text, no paid requests in tests, no private sample import into public fixtures.
- No nested subagents. Task1 owns only files below; parent owns native integration/UI/LLM adapter.

## Task 1: Context store, reversible history kernel and bounded GM planner

Own `src/core.mjs`, `src/store.mjs`, `src/planner.mjs`, `tests/core.test.mjs`, `tests/store.test.mjs`, `tests/planner.test.mjs`.

- [ ] RED/GREEN behavior first; implement meaningful public operations, no tests mirroring private functions.
- [ ] Export `ContextError(code,message,status=400)`, `validateSettings(value)`, `buildHistory(history,{recentTurns=5,representations={}}={})`, `compileMaterials({history,databaseEntries=[],notes='',unresolved=[],maxChars=24000})` from core.mjs. Formal history records `{id,anchor,turn,action,text,summary?,source}` use stable id/source supplied by host. Reject duplicates/invalid refs. History representations full/summary/index; recent defaults full, older defaults summary when actual summary exists, otherwise explicitly mark needsSummary (do not call an excerpt a summary). Preserve original input and return source references. compileMaterials produces serializable frozen `{history:[{id,mode,content,source}],entries:[Entry],guidance,unresolved,recentProse:[full text],chars}`; enforce aggregate rendered JSON char budget, not just bodies. Fail MATERIAL_BUDGET/409 instead of dropping required material.
- [ ] Export async `createContextStore({directory})` returning `view(sessionId,{activeAnchors?}={}) -> {revision,settings,representations,unresolved}`, `configure(sessionId,{settings,expectedRevision})`, `savePlan(sessionId,{representations,unresolved,expectedRevision,anchor})`, `cacheSummaries(sessionId,{summaries:[{id,summary}],expectedRevision})`, `forkSession(fromId,toId,{activeAnchors,expectedRevision})`. Default settings `{enabled:true,recentTurns:5,maxChars:24000,maxSteps:8}` with positive integer bounded settings. Store semantic immutable plans anchored to canonical assistant message IDs, apply only activeAnchors when supplied. Summaries are a cache keyed canonical narrative id; host only passes active history to planner, so old cached ids never return absent records. Human configure only settings; no whole-history mutation. Atomic JSON rename and shared process-local directory queue; hash data identifiers, revisions required on writes, detached reads. Source text remains provided by DSH; never delete it. Fork captures active parent representations/unresolved into independent child baseline.
- [ ] Export `createPlanner({store,callModel,resolveModels?,publish?}) -> {prepare(input)}`. Input `{sessionId,anchor,packet,history,database?,baseModel,signal}`. callModel receives `{sessionId,stageId,config,system,input,signal}`, returns `{text,config?,usage?,finish?}`. Stage IDs `rp-context.prepare` and `rp-context.summarize`; system markers `RP_CONTEXT_PREPARE`/`RP_CONTEXT_SUMMARIZE`. Route override resolves once per preparation (same shape provider/model/reasoningEffort/maxTokens) and otherwise inherits baseModel. Parent supplies actual model streaming adapter.
- [ ] Database is an optional capability facade captured by parent: `snapshot()->{revision,databaseId,version,entries,notes}`, `search({query,limit?,signal})->{revision,candidates,required,degraded}`, synchronous `apply(entries,operations)->{entries,notes}` (permission-checked pure db executor), synchronous `select(entries,ids)->Entry[]` (required union / disabled rejection), async `commit({operations,expectedRevision,signal})->{revision,...}`. No cross-repo import. Snapshot full entries stay program-local; model initially sees candidates and bounded metadata, not all bodies. In no-DB mode accept empty selection and still manage history.
- [ ] Ensure older history missing actual summaries is summarized in bounded batches using summarize stage, response `{summaries:[{id,summary}]}` with exact active ids; no hidden reasoning or arbitrary script handling. Cache summaries with explicit revision. At most8 records/batch and input char guard; report oversize rather than pretending truncate is a faithful summary. A default deterministic summary already supplied by host may avoid model calls. Ignore untrusted script/macro claims in record text.
- [ ] GM preparation loop max settings.maxSteps. JSON response `{readEntries?:[id],search?:[query],databaseOperations?:[],readHistory?:[id],historyOperations?:[{id,mode,summary?}],selectedEntries?:[id],notes?:string,unresolved?:[string],commit:boolean}` only. Initial candidate retrieval query uses packet playerAction/sceneInstruction/visibleConsequences, and model gets metadata catalog page plus candidate list and history representations. On-demand history read returns exact text/refs, database read returns only allowed staged entry bodies. Search must query the full enabled database and can discover entries outside initial candidates. Stage ops in detached snapshot, all reads/selection obey db.apply/select, unknown/disabled/malformed ops become safe diagnostics and allow bounded correction. No GM flag/source mutation. Summary/index/full operations apply to exact active history IDs; originals preserved. Notes/unresolved remain distinct from story facts.
- [ ] On valid commit: enforce current context revision, aggregate material budget and required policy; then atomically submit accumulated DB ops once against captured DB revision, persist context plan against captured context revision, freeze snapshots and refs. A database change is its own transaction; do not later undo merely because writer fails. Config/version conflicts stop without silent rebase. Return `{id,materials,database?:{databaseId,version,revision,entryRefs},models,steps,degraded,revision}`. Emit bounded prepared/running/complete/failed/cancelled stage metadata, no prose/history bodies. Do not return partial material as success at step limit or budget error.
- [ ] Tests: recent window, older summaries, reversible exact expansion, index fold, source preservation, inactive plan filtering, fork/restart/conflict, candidate-outside search, locked/disabled rejection with correction, required union, local staged edits only once, frozen exact writer material after source edits, history missing summary stage, no-DB mode, model-route snapshot, abort/maxSteps/budget/revision rejection.
